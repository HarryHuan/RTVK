# 面向颗粒堆积体的实时仿真与渲染：近期论文调研与硕士创新实现计划

> 生成日期：2026-07-16  
> 适用项目：RTVK  
> 本报告基于《开题报告分析报告.md》《细化技术方案.md》以及近年颗粒仿真、实时渲染、GPU 求解与数据驱动模拟相关论文整理，目标是给出一条满足硕士毕业要求、工程可落地、论文可论证的创新路线。

---

## 一、结论先行

本课题不宜把创新点放在“提出一个全新的颗粒物理模型”上，这条路线理论门槛高、验证成本大、容易失控。更稳妥的硕士路线是：

1. 以 **PBD/XPBD 风格的约束求解** 作为实时仿真核心，面向颗粒堆积体设计 **自适应约束分层求解策略**。
2. 以 **Vulkan Compute + 空间哈希** 作为性能支撑，实现从 CPU 参考求解到 GPU 并行求解的对照闭环。
3. 以 **屏幕空间颗粒表面重建 + 材质参数化** 作为渲染创新，实现沙、土、煤三类颗粒外观差异。
4. 以 **LLM 文本到结构化参数映射** 作为系统交互创新，但必须加入 schema 校验、范围裁剪和用户确认，避免大模型输出直接破坏仿真稳定性。

建议论文主创新点表述为：

- **创新点一：面向颗粒堆积体实时仿真的自适应分层 PBD 求解方法。**
- **创新点二：仿真与渲染共享数据的 Vulkan GPU 管线及稳定性验证机制。**
- **创新点三：面向沙/土/煤颗粒堆积体的屏幕空间渲染与材料参数映射。**
- **创新点四：自然语言驱动的颗粒场景参数生成与安全应用机制。**

其中前三点是主线，第四点是系统完整性和应用创新点。若时间紧，第四点可以收缩为“文本到参数”的最小可行版本。

## 二、开题报告问题复盘

开题分析中已经指出几个关键风险：

| 风险 | 对毕业论文的影响 | 本报告给出的处理方式 |
|------|------------------|----------------------|
| PBD 改进深度不足 | 容易被认为只是工程复现 | 把改进限定为自适应约束分层，并用实验量化 |
| 渲染真实感主观 | 缺少客观评价 | 加入截图对比、帧率、连续性、材质可辨识度评价 |
| LLM 参数不稳定 | 可能破坏系统可信度 | 只让 LLM 生成候选参数，必须校验和确认 |
| 屏幕空间方法有局限 | 遮挡和离屏粒子处理不足 | 明确适用范围，保留粒子渲染作为回退 |
| 时间有限 | 功能堆叠但主线不稳 | 先稳定 PBD 和 GPU 管线，再做渲染和交互 |

因此，后续开发应该围绕“可运行、可测量、可对比、可写论文”组织，而不是堆功能。

## 三、近期相关论文脉络

### 3.1 DEM/GPU 方向：高真实性但实现成本高

DEM 是颗粒系统的经典高保真方法，适合工业颗粒、机器人地形、月壤/沙土接触等场景。近年趋势是 GPU 加速、复杂形状粒子、工程级验证。

| 文献 | 核心内容 | 对本课题启发 |
|------|----------|--------------|
| Chrono::GPU: An Open-Source Simulation Package for Granular Dynamics Using DEM, 2021 | 使用 GPU DEM 模拟大规模颗粒系统，支持 Hertz/Mindlin 接触、滚动摩擦、黏结等，并报告可扩展到极大规模 DEM 元素 | 可作为“高保真 DEM baseline”和论文背景，但不适合作为本项目主实现 |
| A GPU-accelerated simulator for DEM analysis of granular systems composed of clump-shaped elements, 2023 | 支持由多个球组成的 clump-shaped 元素，并用于月壤、车轮牵引等验证 | 说明非球形粒子和真实工程验证是前沿方向，但实现复杂 |
| GranularGym: High Performance Simulation for Robotic Tasks with Granular Materials, RSS 2023 | 面向机器人任务的 GPU 颗粒模拟，强调并行碰撞检测、SIMT warp divergence 优化和刚体交互 | 可借鉴“GPU 并行碰撞检测”和“任务级评估”思路 |
| NeuralDEM, 2025 | 用神经算子替代 DEM 例程，以连续场方式预测宏观颗粒流动，降低大规模 DEM 成本 | 可作为未来展望，不建议纳入当前硕士主实现 |

判断：

- DEM 更适合高保真工程模拟，但实时交互和 Vulkan 图形集成成本高。
- 本课题应把 DEM 作为论文对比对象和理论背景，不把完整 DEM 作为主线。
- 可以借鉴 DEM 的评价指标：休止角、堆积高度、流动时间、接触稳定性。

参考来源：

- [Chrono::GPU, Processes 2021](https://www.mdpi.com/2227-9717/9/10/1813)
- [GPU-accelerated DEM for clump-shaped elements, arXiv 2023](https://arxiv.org/abs/2307.03445)
- [GranularGym, RSS 2023](https://roboticsconference.org/2023/program/papers/034/)
- [NeuralDEM, Communications Physics 2025](https://www.nature.com/articles/s42005-025-02342-4)

### 3.2 PBD/XPBD/PB-MPM 方向：适合实时交互

PBD 系列方法强调稳定性、可控性和实时性。对于本项目，PBD 的价值在于：实现难度可控，适合与 Vulkan Compute 结合，也符合“实时仿真与渲染”的工程目标。

| 文献 | 核心内容 | 对本课题启发 |
|------|----------|--------------|
| Position Based Dynamics, 2007 | 直接投影位置约束，避免速度层过度振荡，适合实时应用 | 当前 CPU PBD 与 GPU constraint shader 的基础 |
| Unified Particle Physics for Real-Time Applications, 2014 | 使用统一粒子和约束框架处理流体、布料、刚体等 | 支持本课题采用“粒子 + 约束”统一建模 |
| XPBD, 2016 | 引入 compliance 和拉格朗日乘子，使刚度更少依赖时间步和迭代次数 | 可作为后续改进摩擦、黏结约束的理论依据 |
| Interactive High-Resolution Simulation of Granular Material, 2023 | 将少量精确约束颗粒与高效重采样分离，可在交互帧率下达到高粒子数视觉效果 | 启发“仿真粒子”和“渲染粒子/视觉粒子”分离 |
| XPBI, SIGGRAPH Asia 2024 | 将 XPBD 与平滑核、连续介质非弹性模型结合，展示雪、沙、塑性材料实时高分辨率模拟 | 说明 PBD/XPBD 正在向沙、雪等非弹性材料扩展 |
| Position-Based MPM, SIGGRAPH Talks 2024 | 将 MPM 组织为位置约束求解形式，提高实时稳定性 | 可作为未来扩展，不建议当前直接改成 MPM |

判断：

- PBD/XPBD 是本项目最合适的核心方向。
- 创新点不应写成“首次使用 PBD 做颗粒”，而应写成“面向颗粒堆积体的分层、自适应、GPU 化 PBD 求解流程”。
- 可以把 PB-MPM 和 XPBI 放入相关工作，说明本课题选择更轻量的 PBD 颗粒约束方案，是为了服务实时交互和系统集成。

参考来源：

- [Position Based Dynamics, Müller et al. 2007](https://matthias-research.github.io/pages/publications/posBasedDyn.pdf)
- [Unified Particle Physics for Real-Time Applications, NVIDIA 2014](https://matthias-research.github.io/pages/publications/flex.pdf)
- [XPBD, Macklin et al. 2016](https://matthias-research.github.io/pages/publications/XPBD.pdf)
- [Interactive High-Resolution Simulation of Granular Material, arXiv 2023](https://arxiv.org/abs/2308.01629)
- [XPBI, arXiv 2024](https://arxiv.org/abs/2405.11694)
- [Position-Based MPM, EA SEED 2024](https://www.ea.com/seed/news/siggraph2024-pbmpm)

### 3.3 颗粒渲染方向：从真实光传输到实时近似

高质量颗粒渲染的核心问题是：单个颗粒形状、颗粒堆积结构、颗粒间散射都会影响外观。离线渲染方法能做到很真实，但不适合当前实时系统。实时系统应采用屏幕空间重建、简化 PBR、噪声纹理和多尺度近似。

| 文献 | 核心内容 | 对本课题启发 |
|------|----------|--------------|
| Multi-Scale Modeling and Rendering of Granular Materials, SIGGRAPH 2015 | 将颗粒内、颗粒间和大尺度传输分开建模，处理沙、雪、糖等多尺度外观 | 论文中可作为“真实颗粒外观复杂性”的基础文献 |
| Multi-Scale Appearance Modeling of Granular Materials with Continuously Varying Grain Properties, EGSR 2020 | 用预计算和模板 tile 处理大规模、连续变化颗粒光学属性 | 启发材质参数化和多尺度表示 |
| Learning Subsurface Scattering Solutions of Tightly-Packed Granular Media, C&G 2024 | 用神经网络学习紧密堆积颗粒的次表面散射近似 | 可作为最新高质量渲染趋势，不纳入当前主实现 |
| Real-time screen-space particle/fluid rendering 系列 | 在屏幕空间从粒子深度重建连续表面，使用滤波、法线重建、后处理提升外观 | 可直接迁移为本项目屏幕空间颗粒表面重建路线 |

判断：

- 离线多尺度颗粒渲染可作为理论背景。
- 当前项目应采用“粒子点精灵调试 + 屏幕空间深度重建 + 材质参数”的可落地路线。
- 论文中应承认屏幕空间方法局限：离屏粒子和遮挡粒子无法完整参与表面重建。

参考来源：

- [Disney Research: Multi-Scale Modeling and Rendering of Granular Materials, SIGGRAPH 2015](https://studios.disneyresearch.com/2015/07/27/multi-scale-modeling-and-rendering-of-granular-materials/)
- [Eurographics: Multi-Scale Appearance Modeling of Granular Materials, 2020](https://diglib.eg.org/items/b25ecfd7-2610-43ab-aac5-5bd4e8614747)
- [Learning Subsurface Scattering Solutions of Tightly-Packed Granular Media, C&G 2024](https://www.sciencedirect.com/science/article/pii/S0097849324000220)
- [Anisotropic screen space rendering for particle-based fluid simulation, Computers & Graphics 2023](https://eprints.bournemouth.ac.uk/37974/1/Anisotropic-screen-space-rendering-for-particle-based-f_2023_Computers---Gra.pdf)

### 3.4 参数识别与智能交互方向

颗粒材料参数通常难以直观设置。机器人和工业模拟领域已经有通过实验数据反推摩擦、恢复系数等参数的工作。对本项目而言，LLM 不应替代物理标定，而应提供“自然语言到参数初值”的交互入口。

| 方向 | 启发 |
|------|------|
| 从真实堆形/深度图推断材料属性 | 说明摩擦、滚动摩擦、恢复系数等可以通过宏观堆形评价 |
| LLM 文本解析 | 适合把“干燥沙堆”“湿土滑坡”“煤堆”转换为参数初值 |
| schema 校验和范围裁剪 | 保证系统稳定性，是论文系统实现部分的重要贡献 |

参考来源：

- [Inferring the Material Properties of Granular Media for Robotic Tasks, arXiv 2020](https://arxiv.org/abs/2003.08032)

## 四、适合硕士毕业的创新点设计

### 创新点一：自适应分层 PBD 颗粒求解

#### 研究问题

标准 PBD 通常对所有约束使用统一迭代次数。对颗粒堆积体而言，地面/边界/接触约束对稳定性最关键，摩擦和黏结更多影响材料差异。如果所有约束都用同样迭代次数，会造成两个问题：

- 简单场景浪费计算。
- 复杂接触场景穿透仍然明显。

#### 拟提出方法

设计 ACL-PBD，即 Adaptive Constraint Layering PBD：

```text
L1 刚性约束：地面、边界、粒子间接触
L2 摩擦约束：切向位移限制、速度衰减
L3 黏结约束：湿土/弱黏结颗粒，按阈值断裂

每帧统计：
- 最大穿透深度
- 平均穿透深度
- 接触对数量
- 约束投影残差

根据统计结果调整：
- L1 迭代次数
- L2/L3 是否启用
- 松弛系数 omega
```

#### 可实现版本

第一版不必实现完整 XPBD 拉格朗日乘子，可采用简单残差控制：

```text
if maxPenetration > 0.5 * radius:
    L1Iterations = min(base + 3, maxIter)
else if avgPenetration < 0.05 * radius:
    L1Iterations = max(base - 1, minIter)
else:
    L1Iterations = base
```

#### 论文贡献表述

“针对颗粒堆积体接触约束密集且材料约束重要性不同的问题，提出一种自适应分层 PBD 求解策略，将接触、摩擦和黏结约束分层处理，并根据穿透残差动态调整迭代预算，在实时帧率下提升堆积稳定性。”

#### 验证指标

| 指标 | 说明 |
|------|------|
| 最大穿透深度 | 反映稳定性 |
| 平均穿透深度 | 反映整体接触质量 |
| FPS / frame time | 反映实时性 |
| 休止角 | 反映颗粒堆积行为 |
| 堆积高度和扩散半径 | 反映材料差异 |

### 创新点二：Vulkan Compute 颗粒仿真与渲染共享管线

#### 研究问题

传统 CPU 仿真 + GPU 渲染需要频繁上传数据，性能和同步复杂。Vulkan 提供 compute 与 graphics 管线统一管理能力，但实现中容易出现 buffer layout、descriptor、同步和坐标系问题。

#### 拟提出方法

构建一条面向颗粒堆积体的 Vulkan 管线：

```text
GpuParticle SSBO
  |
  +-- integrate.comp
  +-- spatial_hash.comp
  +-- compact.comp
  +-- constraint.comp
  |
  +-- particle.vert / 后续 G-Buffer pass
```

关键工程机制：

- C++/GLSL 共享结构体布局校验。
- shader 编译产物自动复制。
- compute 到 graphics 的同步屏障。
- 调试阶段保留 CPU readback。
- 稳定后切换为 graphics 直接读取 GPU buffer。

#### 论文贡献表述

“设计并实现了基于 Vulkan Compute 的颗粒仿真与渲染统一管线，通过共享 GPU 粒子缓冲区减少数据搬运，并建立 C++/GLSL 数据布局一致性检查和调试读回机制，提高实时颗粒系统开发的稳定性。”

#### 验证指标

| 指标 | 说明 |
|------|------|
| 1000/5000/10000 粒子帧率 | 性能扩展性 |
| compute 耗时 | 仿真瓶颈分析 |
| CPU readback 开/关对比 | 数据路径优化收益 |
| 运行稳定时间 | 工程可靠性 |

### 创新点三：面向沙/土/煤的屏幕空间颗粒渲染

#### 研究问题

直接绘制点精灵能验证仿真，但颗粒堆积体缺少连续表面和材料质感。完整离线路径追踪不适合实时系统。

#### 拟提出方法

采用渐进式渲染：

```text
R1: 点精灵粒子渲染
R2: 粒子深度 + 球面法线 + 基础光照
R3: 屏幕空间深度滤波 + 法线重建 + PBR 近似材质
```

材料参数：

| 材料 | 颜色 | 粗糙度 | 黏结/湿度表现 |
|------|------|--------|---------------|
| 沙 | 浅黄、偏高亮 | 高 | 低黏结 |
| 土 | 褐色、低饱和 | 中高 | 可引入湿度 |
| 煤 | 深黑、低反照率 | 中 | 低黏结，可有高对比 |

#### 论文贡献表述

“提出一种面向颗粒堆积体的实时屏幕空间渲染流程，结合粒子深度滤波、法线重建和参数化材质模型，在保持实时性的同时增强沙、土、煤颗粒材料的视觉区分度。”

#### 验证指标

| 指标 | 说明 |
|------|------|
| 点精灵 vs 屏幕空间渲染截图 | 主观对比 |
| FPS 变化 | 渲染开销 |
| 材质可辨识度 | 用户问卷或简单评分 |
| 边缘连续性 | 定性截图分析 |

### 创新点四：自然语言驱动的仿真参数生成与安全应用

#### 研究问题

颗粒仿真参数较多，普通用户难以直接理解摩擦、黏结、恢复系数、粗糙度等数值。LLM 能把自然语言描述转成结构化参数，但输出不稳定。

#### 拟提出方法

```text
用户输入
  |
  v
LLM 生成 JSON 候选参数
  |
  v
schema 校验 + 范围裁剪 + 默认值回填
  |
  v
用户确认
  |
  v
更新 SimParams / RenderParams
```

必须限制：

- 不允许 LLM 直接执行命令。
- 不允许跳过参数校验。
- 参数变化必须能重置和回滚。

#### 论文贡献表述

“设计一种面向颗粒堆积体场景的自然语言参数映射机制，将用户描述解析为受约束的仿真和渲染参数，并通过 schema 校验、范围裁剪和用户确认保证系统稳定性。”

#### 验证指标

| 指标 | 说明 |
|------|------|
| 参数解析成功率 | 常见描述能否得到合理参数 |
| 越界参数裁剪正确率 | 稳定性 |
| 用户确认前后效果 | 交互可控性 |

> 面向颗粒堆积体的实时仿真与渲染

```text
需求：颗粒堆积体需要实时、稳定、可交互、可视化
  |
  v

  v
加速：Vulkan Compute + 空间哈希解决规模和性能
```

## 六、详细实现计划

### 阶段 A：当前系统稳定化

时间建议：1-2 周。

目标：

- 让当前 GPU PBD 路径稳定运行。
- 确保粒子下落、地面碰撞、暂停/恢复、视口方向全部正确。

任务：

- 梳理 `GpuParticle` 与 shader struct 布局。
- 保留 `static_assert` 和 offset 检查。
- 增加简单读回统计：最小 Y、最大 Y、平均速度、NaN 计数。
- 在 UI 显示粒子数量、运行状态。
- 实现“重置模拟”按钮。

验收：

- 1000 粒子运行 60 秒无崩溃。
- 暂停后读回位置保持不变。
- 运行后粒子随重力下落并停在地面约束上方。

### 阶段 B：PBD 约束完善

时间建议：2-3 周。

目标：

- 完善接触约束、摩擦约束、边界约束。
- 建立 CPU/GPU 行为对照。

任务：

- CPU `PBDSolver` 增加摩擦和简单材料参数。
- GPU `constraint.comp` 增加同等逻辑的简化版本。
- 记录每帧接触数量和穿透残差。
- 实现固定迭代 vs 自适应迭代对比。

验收：

- 同一初始场景下，CPU/GPU 堆积趋势一致。
- 自适应分层策略在相近帧率下减小最大穿透，或在相近穿透下提高帧率。

### 阶段 C：Vulkan Compute 管线优化

时间建议：2 周。

目标：

- 减少不必要 CPU readback。
- 完善 GPU 空间哈希和约束投影性能。

任务：

- 检查 `spatial_hash.comp`、`compact.comp` 的桶统计正确性。
- 增加 GPU 时间戳或 CPU 侧分段计时。
- 逐步尝试渲染直接读取 GPU particle buffer。
- 保留 debug readback 开关。

验收：

- 10000 粒子能达到或接近 30 FPS。
- compute 各阶段耗时可统计。
- Debug 模式和正常模式均可运行。

### 阶段 D：屏幕空间渲染

时间建议：3-4 周。

目标：

- 从简单点精灵过渡到具有颗粒材料感的实时渲染。

任务：

- 实现粒子深度输出。
- 实现深度双边滤波。
- 从深度重建法线。
- 加入沙/土/煤基础材质参数。
- 加入渲染模式切换：点精灵 / 屏幕空间。

验收：

- 三类材料视觉上可区分。
- 屏幕空间模式相比点精灵具有更连续的表面观感。
- 10000 粒子下渲染仍保持可交互帧率。

### 阶段 E：LLM 参数交互

时间建议：2 周。

目标：

- 实现文本到参数的稳定交互。

任务：

- 设计 JSON schema。
- 实现参数校验、范围裁剪、默认值回填。
- UI 中显示解析结果。
- 用户确认后应用参数并重置仿真。

验收：

- “干燥沙堆”“湿土滑坡”“煤堆”能生成合理参数。
- 无效输入不会导致崩溃或异常参数。

## 七、实验设计细化

### 7.1 仿真性能实验

| 实验 | 自变量 | 因变量 | 预期结论 |
|------|--------|--------|----------|
| 粒子数量扩展 | 1000/5000/10000/50000 | FPS、compute time | GPU 管线可扩展 |
| 迭代次数 | 1/3/5/8/12 | 穿透深度、帧率 | 迭代越多越稳定但越慢 |
| 自适应 vs 固定迭代 | 固定 5 次 / 自适应 | 平均穿透、帧率 | 自适应策略更均衡 |
| CPU vs GPU | 相同场景 | 单帧耗时 | GPU 加速有效 |

### 7.2 物理合理性实验

| 实验 | 方法 | 指标 |
|------|------|------|
| 休止角 | 粒子自由堆积后测量边坡角 | 与沙/土/煤典型范围对比 |
| 扩散半径 | 同一高度释放颗粒 | 不同摩擦参数下的铺展范围 |
| 堆积稳定时间 | 从释放到平均速度低于阈值 | 稳定性 |
| 边界约束 | 粒子撞击容器边界 | 是否越界 |

### 7.3 渲染实验

| 实验 | 对比 | 指标 |
|------|------|------|
| 点精灵 vs 屏幕空间 | 同一帧截图 | 表面连续性、主观评分 |
| 材料切换 | 沙/土/煤 | 颜色、粗糙度、视觉辨识度 |
| 后处理开关 | AO/FXAA/Tone Mapping | 帧率与视觉质量 |

### 7.4 交互实验

| 输入 | 预期 |
|------|------|
| “干燥沙堆，颗粒较细，流动性强” | 沙，低黏结，中等摩擦，浅黄色 |
| “湿土滑坡，比较黏” | 土，高黏结，高摩擦，深褐色 |
| “黑色煤堆，颗粒较粗” | 煤，低反照率，中等摩擦，较大半径 |
| “随便来一个特别夸张的火星泥浆瀑布” | 参数被裁剪，系统提示确认 |

## 九、不建议纳入主线的方向

以下方向可以写入展望，但不建议作为硕士主线：

| 方向 | 原因 |
|------|------|
| 完整高保真 DEM | 接触模型、时间步稳定、验证成本过高 |
| 非球形 clump 颗粒 | 数据结构和碰撞检测复杂 |
| PB-MPM 完整实现 | 理论和工程量都较大，容易偏离当前项目 |
| NeuralDEM 代理模型 | 需要训练数据和模型工程，毕业风险高 |
| 离线路径追踪颗粒渲染 | 与实时系统目标不一致 |
| 图片多模态参数识别 | 数据和稳定性问题比文本更复杂 |
