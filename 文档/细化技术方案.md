## 二、实时仿真算法（第三章细化）

### 2.1 基础PBD流程

PBD核心循环（每帧执行）：

```
for each frame:
    1. 外推速度: v_i ← v_i + Δt * f_ext / m_i
    2. 预测位置: p_i ← x_i + Δt * v_i
    3. 碰撞检测: 生成碰撞约束集 C(p_1, ..., p_n)
    4. 约束投影: 迭代求解约束，修正 p_i
    5. 更新速度: v_i ← (p_i - x_i) / Δt
    6. 更新位置: x_i ← p_i
```

### 2.2 改进点：自适应约束分层求解 (Adaptive Constraint Layering, ACL)

**问题**：标准PBD对所有约束采用统一迭代次数，导致简单场景浪费计算、复杂场景精度不足。

**改进方案**：

- **分层约束分类**：
  - L1（刚性约束）：位置约束、碰撞穿透校正 → 每帧 5-8 次迭代
  - L2（柔性约束）：摩擦、黏结、密度 → 每帧 2-3 次迭代
  
- **自适应松弛因子**：
  - 根据残差动态调整 ω：`ω = clamp(k / (avg_residual + ε), 0.2, 1.0)`
  - 收敛快时自动减小迭代次数，发散时增加

- **Gauss-Seidel + Jacobi 混合求解**：
  - 层内使用GS保证收敛速度
  - 层间使用Jacobi便于GPU并行化

### 2.3 颗粒物理模型

| 参数 | 符号 | 说明 | 沙堆典型值 | 土壤典型值 | 煤堆典型值 |
|------|------|------|-----------|-----------|-----------|
| 密度 | ρ | 颗粒质量/体积 | 1600 kg/m³ | 1800 kg/m³ | 1300 kg/m³ |
| 摩擦系数 | μ | 颗粒间摩擦 | 0.6 | 0.8 | 0.5 |
| 黏结力 | c | 颗粒间黏结强度 | 0 | 0.5-2.0 kPa | 0 |
| 恢复系数 | e | 碰撞弹性 | 0.3 | 0.1 | 0.4 |
| 休止角 | θ | 自然堆积角度 | 30-35° | 35-45° | 25-30° |

**物理约束**（PBD中实现）：

1. **接触约束**：`C(p_i, p_j) = |p_i - p_j| - (r_i + r_j) ≥ 0`
2. **摩擦约束**：`C_t = |Δp_t| - μ * Δp_n ≤ 0`（库伦摩擦模型）
3. **黏结约束**：`C_b = |p_i - p_j| - d_break > 0 ? 释放 : 保持`（弹簧约束）
4. **地面约束**：`C(p_i) = p_i.y - r_i ≥ 0`

### 2.4 碰撞检测优化：Vulkan Compute 空间哈希

**空间哈希方案**：

```
数据结构（Shader Storage Buffer）:
  - hash_keys: uint32[]     // 每个粒子的哈希键
  - cell_starts: uint32[]    // 每个网格桶的起始索引
  - cell_counts: uint32[]    // 每个网格桶的粒子数量
  - sorted_indices: uint32[] // 按哈希排序的粒子索引

Vulkan Compute Pipeline 执行步骤:

Dispatch 1 - 构建哈希 (workgroup: 64, total: particle_count)
  for each particle i:
    cell_key = hash(floor(p_i / cell_size)) % TABLE_SIZE
    hash_keys[i] = cell_key

Dispatch 2 - 基数排序 (workgroup: 64)
  radix_sort(hash_keys, sorted_indices)  // 按哈希键排序

Dispatch 3 - 构建桶索引 (workgroup: 64, total: TABLE_SIZE)
  // 并行扫描 sorted_indices，填充 cell_starts / cell_counts
  prefix_sum(cell_counts, cell_starts)

Dispatch 4 - 碰撞检测 (workgroup: 64, total: particle_count)
  for each particle i:
    cell = hash_keys[sorted_indices[i]]
    for each neighbor_cell in 3x3x3:
      for each j in cell_starts[neighbor_cell] .. cell_starts[neighbor_cell]+cell_counts[neighbor_cell]:
        if |p_i - p_j| < r_i + r_j:
          constraints[atomic_add++] = (i, j)
```

### 2.5 GPU加速管线（Vulkan Compute）

```
Vulkan Compute Pipeline:
┌──────────────────────┐
│  VkDescriptorSetLayout │
│  binding 0: SSBO 粒子位置 (vec4)    │
│  binding 1: SSBO 粒子速度 (vec4)    │
│  binding 2: SSBO 哈希表 (uint32)    │
│  binding 3: SSBO 约束列表           │
│  binding 4: Uniform 仿真参数         │
└──────────────────────┘

帧循环流水线 (Timeline Semaphore 同步):

Frame N:
  CPU提交: 外推速度 Compute Shader
  CPU提交: 空间哈希 Compute Shader
  CPU提交: 碰撞检测 Compute Shader
  CPU提交: 约束投影 (多次迭代) --- 循环
  CPU提交: 更新速度位置 Compute Shader
  
  ↑ 所有Compute完成 → Signal Timeline Semaphore
  
  CPU提交: Graphics Pipeline (渲染)
    使用 Compute 输出的粒子位置 SSBO 作为 Vertex Buffer
    ↓
  Present (Vulkan swapchain)

帧间并行:
  Frame N 的 Compute 与 Frame N-1 的 Graphics 
  通过 Timeline Semaphore 实现重叠执行
```

## 三、实时渲染方案（第四章细化）

### 3.1 渲染管线流程 (Vulkan Graphics Pipeline)

```
每帧渲染 (Vulkan Render Pass):

  Pass 1 - G-Buffer Pass
    Subpass 0:
      - 从粒子SSBO读取位置
      - 顶点着色器：点精灵扩展为屏幕四边形
      - 片元着色器：输出深度+法线+基础颜色到GBuffer
      - Attachment: VK_FORMAT_R16G16B16A16_SFLOAT (法线/颜色)

  Pass 2 - 屏幕空间重建 (Compute Shader)
    - 输入: GBuffer 深度纹理
    - 输出: 重建表面纹理
    - 双边滤波 → 空洞填补

  Pass 3 - 光照 Pass
    Subpass 1:
      - 延迟光照: 读取GBuffer + 重建纹理
      - Cook-Torrance BRDF 计算
      - 输出: HDR 颜色缓冲区

  Pass 4 - 材质叠加 Pass
    Subpass 2:
      - 根据颗粒类型叠加噪声散射纹理
      - 粗糙度 / 金属度微调

  Pass 5 - 后处理 Pass
    Subpass 3:
      - SSAO (Screen Space Ambient Occlusion)
      - Tone Mapping (ACES Filmic)
      - FXAA 抗锯齿
      - Dear ImGui 叠加绘制

  VK_SUBPASS_CONTENTS_INLINE (所有Subpass在同一个RenderPass内，
  利用Vulkan subpass依赖实现TBDR友好的带宽优化)
```

### 3.2 屏幕空间表面重建

采用 **各向异性表面重建** 方法（Adaptive Surface Splatting）：

```
对于每个屏幕像素 (x, y):
  - 提取该像素处深度范围 [z_min, z_min + depth_threshold] 内的 N 个粒子
  - 按投影椭圆（splat）权重加权平均:
    P_surface = Σ (w_i * P_i) / Σ w_i
    w_i = exp(-(d_screen² / (2 * σ²))) * exp(-(Δz² / (2 * σz²)))
  - 法线重建: 从重建位置计算屏幕空间导数
    normal = normalize(cross(dFdx(P_surface), dFdy(P_surface)))
```

### 3.3 差异化材质渲染

Vulkan 实现方式：通过 **Push Constants** 或 **Uniform Buffer** 传递材质参数，片元着色器中根据 `material_id` 分支计算。

```
// Vulkan GLSL 片元着色器 (经过 glslc 编译为 SPIR-V)
#version 460
#extension GL_EXT_nonuniform_qualifier : enable

layout(push_constant) uniform MaterialParams {
    int material_type;   // 0:沙, 1:土, 2:煤
    float roughness;
    float metallic;
    float wetness;       // 湿度遮罩 (0-1)
} mat;

layout(binding = 3) uniform sampler2D noise_tex;

vec3 shade_granular(vec3 N, vec3 V, vec3 L) {
    vec3 albedo;
    float r = mat.roughness;
    
    // 从噪声纹理采样微表面变化
    float noise = texture(noise_tex, uv * 32.0).r;
    
    switch (mat.material_type) {
        case 0:  // 沙堆 - 高粗糙度，淡黄色
            albedo = vec3(0.76, 0.70, 0.50);
            r = mix(r, 0.95, noise * 0.15);
            break;
        case 1:  // 土壤 - 中等粗糙度，褐色，湿度影响
            albedo = vec3(0.45, 0.30, 0.15);
            r = mix(r, r * (1 - mat.wetness * 0.5), noise * 0.2);
            break;
        case 2:  // 煤堆 - 低粗糙度，黑色，微金属
            albedo = vec3(0.08, 0.08, 0.08);
            r = mix(r, 0.45, noise * 0.15);
            break;
    }
    
    return cook_torrance(N, V, L, r, mat.metallic, albedo);
}
```

### 3.4 渲染优化策略

| 技术 | Vulkan 实现方式 | 预期收益 |
|------|---------------|---------|
| 实例化渲染 | `vkCmdDrawIndexedIndirect` + 间接缓冲区 | 单DrawCall渲染全部粒子 |
| LOD | 不同LOD级别的粒子簇代理 + 不同粒度Mesh | 远距离减少顶点数 |
| 多视口 | 一个RenderPass内并行渲染ShadowMap | 避免额外的Pass切换 |
| 显存紧凑 | 使用 `VK_KHR_buffer_device_address` 减少间接跳转 | 降低带宽 |
| 异步计算 | 独立Compute Queue + Timeline Semaphore | Compute与Graphics重叠 |

## 七、Qt+Vulkan 迁移要点

### 由 OpenGL 切换到 Vulkan 的核心变化

| 方面 | OpenGL 方案 | Vulkan 方案 | 影响 |
|------|-----------|------------|------|
| 上下文管理 | QOpenGLWidget 自动管理 | QVulkanWindow 提供 VkDevice | 需手动处理 Queue/Fence/Semaphore |
| Shader | GLSL 运行时编译 | GLSL→SPIR-V (glslc) 离线编译 | 增加编译步骤，但更稳定 |
| 内存管理 | 自动 (glBufferData) | 手动 VkBuffer/VkDeviceMemory | 更复杂但更可控 |
| 多线程 | 单上下文限制 | 多 Queue 并行 | 仿真+渲染可真正并行 |
| 调试 | glDebugMessageCallback | Vulkan Validation Layers | 启用 Vulkan SDK 层 |
| 集成 | QOpenGLWidget 直接使用 | QVulkanWindow 需自定义渲染器 | 封装稍多 |

### QVulkanWindow 核心集成代码骨架

```cpp
// QVulkanWindow 子类
class GranularVulkanWindow : public QVulkanWindow {
    Q_OBJECT
public:
    class Renderer : public QVulkanWindowRenderer {
        // vkInitResources() — 创建管线、DescriptorSet、Buffer
        // vkStartNextFrame() — 构建CommandBuffer
        // vkFrameSubmitted() — 帧同步
    };
    
    QVulkanWindowRenderer* createRenderer() override {
        return new Renderer(this);
    }
    
signals:
    void simulationParamsChanged(const SimParams& params);
    
public slots:
    void onLLMResponse(const QJsonObject& params);
};
```
